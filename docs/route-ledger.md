# Trustora route ledger

The Astro app is static, server-first, and uses trailing-slash URLs. Every route below has one clear job, a visible primary action, and a deliberately different editorial signature.

| Route | Job | Primary action | Early visual signature |
| --- | --- | --- | --- |
| `/` | Establish Trustora’s point of view and introduce EoR | Explore services | Dark, full-bleed hero with team-table image |
| `/services/` | Show the EoR service family | Start with EoR | Mint service map with skyline image |
| `/services/employer-of-record/` | Explain the core EoR engagement | Talk through a role | Mint hero, four-step path, human-in-the-loop argument |
| `/services/employee-intelligence/` | Explain specialist talent alongside the EoR layer | Discuss a specialist hire | Operations image, capability path, employment boundary |
| `/services/global-payroll/` | Explain payroll coordination | Discuss payroll | Operations image and recurring-cycle path |
| `/services/contractor-to-employee/` | Explain a considered conversion path | Review a relationship | Workplace collage and classification guardrails |
| `/services/global-mobility/` | Explain cross-border movement support | Map a move | Remote-work image and handoff model |
| `/services/people-operations/` | Explain the post-hire operating layer | Shape the employee experience | People-at-work image and lifecycle path |
| `/what-is-eor/` | Give prospective buyers a plain-language EoR explainer | Read the EoR guide | Educational cream page with process map |
| `/insights/` | Create an editorial entry point | Read the featured article | Featured story followed by article index |
| `/insights/what-is-employer-of-record/` | Define EoR and its boundaries | Start a conversation | Article hero, contents rail, source notes |
| `/insights/eor-with-employee-intelligence/` | Explain the new EoR + specialist talent position | Discuss a specialist hire | Article hero, diagnostic questions, boundary note |
| `/insights/why-companies-use-eor/` | Explain the business case without hype | Explore EoR | Benefit-led article with practical questions |
| `/insights/the-trust-layer-in-global-employment/` | Make integrity a service differentiator | Meet Trustora | Trust-led article with principles |
| `/insights/eor-vs-peo/` | Clarify a common model comparison | Ask which model fits | Comparison table and caveats |
| `/eor/` | Convert a high-intent visitor | Request an EoR conversation | Focused squeeze page with country/role/context form |
| `/eor-readiness/` | Convert an earlier-stage visitor | Request a readiness review | Checklist-led squeeze page |
| `/about/` | Explain who Trustora is and how it works | Start a conversation | Integrity principles and team image |
| `/careers/` | Invite aligned operators to connect | Email the team | People image and culture statement |
| `/contact/` | Provide a low-friction contact route | Email Trustora | Simple contact form with scope note |
| `/legal/privacy/` | Set a plain-language privacy boundary | Return home | Quiet legal layout |
| `/legal/terms/` | Set a plain-language service boundary | Contact Trustora | Quiet legal layout |
| `/404/` | Recover a lost visitor | Return home | Dark recovery state |

The two conversion routes intentionally use a reduced header and a single dominant form. The forms use `mailto:` as a static-site fallback and make the next step, expected information, and advisory boundaries explicit.
